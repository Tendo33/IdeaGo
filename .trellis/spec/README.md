# IdeaGo Main Trellis Spec

This spec is the AI collaboration source of truth for the `main` branch of
IdeaGo. The branch is the anonymous/personal deployment edition of the product.
It keeps the Source Intelligence V2 analysis core and intentionally excludes
hosted runtime concerns such as auth, Supabase ownership, Stripe billing,
LinuxDo sessions, profiles, quotas, and admin APIs.

Use the `saas` branch for the hosted/commercial edition. Do not copy
hosted-only requirements from `saas` into `main` unless the task explicitly says
both branches should change.

## Product Contract

IdeaGo turns a rough startup idea into a decision-first validation report backed
by live evidence from Tavily, Reddit, GitHub, Hacker News, App Store, and Product
Hunt. Reports stay ordered as:

1. recommendation and why-now
2. pain signals
3. commercial signals
4. whitespace opportunities
5. competitors
6. evidence
7. confidence

Frontend report sections and `SectionNav` anchors must preserve that order
one-to-one. `pipeline/merger.py` remains deterministic competitor dedupe only.
Whitespace, entry-wedge, and opportunity synthesis belong in
`pipeline/aggregator.py`.

## Runtime Contract

- Anonymous idea submission.
- `/reports/new` transient creation state before the persisted report id is
  known.
- SSE progress streaming with capped reconnects and `/status` fallback.
- Local file-cache persistence for report history.
- Markdown export.
- Stable anonymous `X-Session-Id` generated by the browser client.
- Local SQLite LangGraph checkpoints.
- No account ownership model.

## Baseline Stack

- Python 3.10+
- `uv`
- FastAPI + Pydantic v2 + `pydantic-settings`
- LangGraph + LangChain OpenAI
- local file cache for reports
- SQLite checkpoints for pipeline state
- React 19
- TypeScript strict mode
- Vite 7
- Tailwind CSS v4
- React Router 7
- `pnpm`
- Vitest + Testing Library + jsdom

## Project Bias

- Keep changes small, typed, and explicit.
- Preserve branch-specific behavior: anonymous/personal behavior belongs on
  `main`; hosted SaaS behavior belongs on `saas`.
- Update this spec when behavior, structure, scripts, adapters, public APIs,
  verification commands, or stack choices change.
